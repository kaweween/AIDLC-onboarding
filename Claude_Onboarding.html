✳️ Orientation

An agent that reads, plans, edits, runs and checks

Claude Code works in a loop: gather context, take an action (read a file, run a command, edit code), check the result, repeat. You set how much it may do without asking. Project files tell it how your team works.

Terminal CLI

claude in your repo. The fullest feature set: plan mode, subagents, skills, hooks, MCP, checkpoints.

IDE extensions

VS Code (and forks) and JetBrains. Inline diffs, selection context, the same sessions and settings.

Desktop & web

Run several sessions side by side, or in cloud containers that clone your repo, so you can hand off work and check from your phone.

GitHub Actions

anthropics/claude-code-action: mention @claude on an issue or PR, or run it on events and schedules.

Headless & Agent SDK

claude -p for scripts and CI. The Agent SDK (TypeScript/Python) for building your own agents on the same engine.

Extensions

CLAUDE.md, skills, subagents, hooks, MCP servers and plugins that bundle them.

🔑 Access

What an admin sets up first

  • How people sign in: Claude Team/Enterprise seats that include Claude Code, the Claude API (Console), or a cloud provider (Amazon Bedrock, Google Vertex AI, Microsoft Foundry) or an enterprise gateway.
  • Managed settings: an org-wide policy file that users can't override. Use it for denied commands, allowed MCP servers and default permission mode.
  • Deny list: for example Bash(curl:*), Read(./.env), Read(./secrets/**).
  • MCP allowlist: the servers your security team has reviewed.
  • GitHub: install the Claude GitHub app on the repos where @claude may run. Store the API key or cloud credentials as repo/org secrets.
  • Usage & analytics: who uses it, spend, and accepted lines. Set spend limits per workspace.
  • Branch protection on main: Claude's PRs follow the same review rules.

Use…When you want…
CLAUDE.mdFacts Claude needs every time (build/test commands, rules). Keep it short. Use @path imports for detail.
SkillA repeatable procedure that loads only when needed (for example "add an endpoint", "write a migration").
SubagentA focused worker with its own context window (reviewer, test writer, explorer), so the main conversation stays clean.
HookSomething that must always happen, enforced by the harness, not by the model (format after edit, block edits to migrations/).
PluginA bundle of the above to share across repos via a marketplace.

📅 Rollout

A 30-60-90 day rollout for one team

Days 1–30 · Pair

CLI or IDE in default permission mode. CLAUDE.md committed. Plan mode for anything over ~50 lines. /code-review before every PR. DORA baseline recorded.

Days 31–60 · Automate

Hooks for format, lint and tests. Two subagents, one skill. @claude on PRs. AI-DLC classic for one real epic.

Days 61–90 · Parallelise

Several sessions on separate worktrees or cloud sessions, one per Unit. Headless runs in CI. Compare metrics against the baseline.

⛔

Rules from day one: don't use --dangerously-skip-permissions outside a throwaway container. Secrets go in the deny list. A person reviews every diff that ships.

❓ FAQ

Questions teams ask in week one

Which permission mode should I use?

Default asks before edits and commands. Accept edits auto-accepts file edits but still asks for commands. Plan is read-only until you approve a plan. Bypass modes skip prompts and belong only in isolated containers. Allow rules for safe commands (for example Bash(dotnet test:*)) cut down on prompts.

CLAUDE.md is getting long. What do I do?

Keep only what's needed every session. Move procedures into skills (loaded when relevant), move rules that must never be broken into hooks or the deny list, and use nested CLAUDE.md files per folder.

Why use a subagent instead of just asking?

A subagent works in its own context window and returns only a summary. Exploring a large codebase or reviewing a diff that way keeps your main conversation focused and cheaper.

Does Claude Code send our code anywhere?

Code it reads goes to the model provider you configured (Anthropic, Bedrock, Vertex AI or Foundry) under that provider's data terms. Commercial terms don't train on your data by default. Check your org's agreement.

How is this different from running /aidlc?

Plain Claude Code is flexible: you decide the steps. /aidlc adds a method on top: scopes, ordered stages, approval gates, review agents, guards and an audit record. Use plain Claude Code for small tasks and AI-DLC for features and projects.

Can two people work in the same repo with Claude at once?

Yes. Use separate branches or git worktrees per session. AI-DLC lets several people answer and approve on one shared record.

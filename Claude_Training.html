Claude AI SDLC: Training Path

Six modules from your first session to Claude in CI and AI-DLC on top. About 9 hours in total, with a lab in each module and a knowledge check at the end.

L100 → L300~9 h6 labs12-question check
⌂ All guides
ℹ️

Before you start: read the Onboarding guide. Labs need Claude Code signed in, a sandbox repo with tests, and (for M5) a GitHub repo you can add workflows to.

Modules

L100

M1 · How an agentic coding loop works

45 min
  • Gather context → act → check → repeat. Tools: read, search, edit, bash, web, MCP.
  • The context window: why /clear, /compact and subagents matter.
  • Surfaces: CLI, IDE, desktop, web, GitHub, Agent SDK.
Lab 1: Ask Claude to explain a module you don't know. Then ask it to prove one claim by running a test. Note where it read versus where it guessed.
L100

M2 · Daily workflow

90 min
  • Explore → plan → code → commit. Plan mode with Shift+Tab.
  • Test-first: write the failing test, make it pass, don't touch the test.
  • Esc, /rewind, @file mentions, images and pasted errors as context.
Lab 2: Fix a real bug test-first in plan mode. Use /rewind at least once on purpose.
L200

M3 · Context engineering

90 min
  • CLAUDE.md hierarchy (user, project, nested), @ imports, keeping it short.
  • Skills: when they load, and bundling scripts with them.
  • Subagents: tools allowlist, descriptions that trigger delegation, parallel exploration.
Lab 3: Write a 30-line CLAUDE.md, one skill and one reviewer subagent. Run the same task before and after, and compare the number of corrections you needed.
L200

M4 · Guardrails: permissions, hooks, MCP

2 h
  • Permission modes; allow/ask/deny rules; precedence (managed → project → user, deny first).
  • Hook events (PreToolUse, PostToolUse, Stop, session events), exit code 2 to block.
  • MCP scopes (local, project .mcp.json, user), approval, least privilege.
Lab 4: Add a deny rule for .env, a format hook and a blocking hook for a protected folder. Try to break each one.
L300

M5 · Claude in CI and automation

2 h
  • /install-github-app and anthropics/claude-code-action: @claude on issues and PRs.
  • Headless: claude -p, --allowedTools, --output-format json.
  • Parallel sessions: git worktrees and cloud sessions. Agent SDK for custom agents.
Lab 5: Add a workflow step that runs claude -p on test failure and posts a 5-line triage comment. Make sure it has read-only tools.
L300

M6 · AI-DLC on Claude Code

90 min
  • Scopes, gates, the record in aidlc/, the 14 agents.
  • Plan approval, guards and sensors as hooks on top of Claude Code.
  • Choosing: plain Claude Code for tasks, /aidlc for features and projects.
Lab 6: Run the AI-DLC greenfield sim, then /aidlc … --scope express on a toy feature for real.

Knowledge check

1. What does plan mode do?

2. A command matches both an allow rule and a deny rule. What happens?

3. You need formatting to run after every edit, without exception. Use…

4. How does a PreToolUse hook block an action?

5. Why delegate codebase exploration to a subagent?

6. A long, rarely-needed procedure belongs in…

7. What does /rewind NOT undo?

8. Which runs Claude non-interactively in a pipeline with limited tools?

9. How do you run two Claude sessions on independent Units safely?

10. Claude edits a test's assertion to make it pass. What do you do?

11. An org wants a deny rule no developer can override. Where does it go?

12. What does /aidlc add on top of plain Claude Code?

Step 1
◎ Orientation

One agent, two places to run it

Codex is OpenAI's software engineering agent. Locally, it edits your checkout inside a sandbox with approval rules you choose. In the cloud, each task gets its own container with your repo, so several tasks can run at once and each ends in a diff or PR.

Codex CLI

Open-source terminal agent (codex). Sandbox + approval modes, AGENTS.md, MCP, skills, /review.

IDE extension

VS Code and compatible editors. Chat, edits and the option to send a task to the cloud and pull the result back.

Codex cloud

Delegated tasks in isolated containers, set up per environment. Run several attempts and pick the best diff. Open a PR from the result.

Code review

Comment @codex review on a GitHub PR, or turn on automatic reviews. It follows review guidance in AGENTS.md.

Automation

codex exec for scripts and CI, the Codex GitHub Action, and the Codex SDK for your own tools.

Integrations

Slack and issue trackers can hand tasks to Codex cloud, depending on your plan and admin settings.

ℹ️

AI-DLC on Codex: aidlc config --harness codex writes .codex/ (with onboarding injected through developer_instructions in .codex/config.toml) and skills under .agents/skills/. You start the method with $aidlc <what you want>, not /aidlc.

🔑 Access

What an admin sets up first

  • Sign-in route: ChatGPT Business/Enterprise/Edu workspace seats (Codex included), or an OpenAI API key for usage-based billing.
  • Workspace settings: turn Codex local and cloud on or off, and choose who may use cloud tasks and code review.
  • GitHub connector: connect the GitHub org and pick which repos Codex cloud may access.
  • Cloud environments: setup script, env vars, secrets (available during setup only) and agent internet access, off by default, or an allowlist.
  • Default local policy: a team config.toml that starts in workspace-write sandbox with on-request approvals.
  • Code review: turn on automatic reviews for chosen repos, or only on request.
  • Branch protection: Codex PRs need the same reviews and checks as anyone's.

📅 Rollout

A 30-60-90 day rollout for one team

Days 1–30 · Local

CLI/IDE in workspace-write + on-request. AGENTS.md merged. @codex review on request. DORA baseline.

Days 31–60 · Cloud

One cloud environment with a working setup script. Small tasks with multiple attempts. Automatic reviews on one repo. $aidlc for one epic.

Days 61–90 · Pipeline

AI-DLC Units fan out as cloud tasks. codex exec triage in CI. Compare metrics against the baseline.

⛔

Rules from day one: no danger-full-access sandbox and no "never ask" approvals on a developer laptop. Keep cloud internet access off unless you need an allowlist. A person merges every PR.

❓ FAQ

Questions teams ask in week one

What's the difference between sandbox and approvals?

The sandbox sets what Codex can technically do (read-only, write inside the workspace, or full access, plus whether the network is allowed). The approval policy sets when it must stop and ask you. You choose both. Most teams use workspace-write with on-request approvals.

Local or cloud?

Use local when you want to steer, need local tools or secrets, or the task is exploratory. Use cloud for clear, independent tasks you want to run in parallel or with several attempts, while you do something else.

Can cloud tasks reach the internet?

During setup, yes (to install dependencies). While the agent works, internet is off by default. You can allow it per environment, ideally to an allowlist of domains.

Does Codex read CLAUDE.md or copilot-instructions.md?

No. Codex reads AGENTS.md. Many teams keep the shared rules in AGENTS.md and point the other tools' files at it.

Why $aidlc and not /aidlc?

In Codex, skills are invoked with $name. Slash commands are reserved for built-in commands such as /review and /init.

✦ Orientation

Four ways to work with Gemini on code

Gemini CLI

Open-source terminal agent (gemini). GEMINI.md context, MCP, custom commands, extensions, sandboxing, checkpoints, headless -p.

Gemini Code Assist

IDE plugin for VS Code and JetBrains with chat, completion and agent mode. Standard/Enterprise editions add admin controls. Enterprise adds code customisation from your private repos.

Code Assist on GitHub

A GitHub app that reviews PRs and summarises them. Ask with /gemini review. Style rules go in .gemini/styleguide.md.

Jules

An asynchronous coding agent. It clones your repo into a cloud VM, shows you a plan to approve, makes the change and publishes a branch or PR.

Automation

google-github-actions/run-gemini-cli for triage, review and scheduled jobs in GitHub Actions.

More

Google also has an agent-first IDE (Antigravity) and Firebase Studio for app prototyping. Check what your org licenses.

📊 DORA

Measure delivery, not keystrokes

DORA (DevOps Research and Assessment, now part of Google Cloud) has studied software delivery for over a decade. Its 2025 State of AI-assisted Software Development report describes AI as an amplifier: it magnifies a team's existing strengths, and its dysfunctions too. Almost every respondent used AI, yet about 30% reported little or no trust in AI-generated code.

GroupMetricQuestion it answers
ThroughputChange lead timeHow long from commit to running in production?
Deployment frequencyHow often do we deploy to production?
Failed deployment recovery timeWhen a deploy breaks production, how fast do we recover?
InstabilityChange failure rateWhat share of deployments need immediate intervention?
Rework rateWhat share of deployments are unplanned, done to fix a user-facing problem?
ℹ️

These metrics apply to every platform in this hub. Use them to compare before and after a Microsoft, Claude, Codex or Gemini rollout. Tool usage stats (suggestions accepted, lines generated) don't tell you whether delivery improved.

🧩 Capabilities

The DORA AI Capabilities Model

DORA's 2025 research names seven capabilities that strengthen AI's positive effect on outcomes. Use them as your rollout checklist.

#CapabilityWhat it looks like in practice
1Clear and communicated AI stancePeople know which tools are allowed, for what, with what data, and that experimenting is expected.
2Healthy data ecosystemsInternal data is high quality, accessible and unified, not scattered and stale.
3AI-accessible internal dataAgents can reach your docs, code and tickets (context files, MCP, code customisation), not just public knowledge.
4Strong version control practicesFrequent commits, and easy rollback when AI-generated changes go wrong.
5Working in small batchesSmall PRs and small deploys, even when AI makes big changes easy to produce.
6User-centric focusTeams aim AI at user outcomes, not at output volume.
7Quality internal platformsGolden paths, CI/CD and self-service that let AI-produced changes flow safely.

🔑 Access

What an admin sets up first

  • Gemini Code Assist Standard or Enterprise licences in a Google Cloud project, assigned to the team. Gemini CLI can sign in with the same Google identity.
  • Data governance: confirm the enterprise data terms, and turn on code customisation (Enterprise) only for approved repos.
  • Gemini Code Assist GitHub app installed on chosen repos, with a team .gemini/styleguide.md.
  • Jules: who may connect which GitHub repos, and the environment setup script.
  • Gemini CLI policy: default approval mode, sandbox, and an approved MCP server list in a shared .gemini/settings.json.
  • DORA data: a way to collect deployments, incidents and PR merges (CI/CD events, incident tool, Git host) into a dashboard.
  • Baseline: four weeks of the five DORA metrics before the rollout.

📅 Rollout

A measured 30-60-90 day rollout

Days 1–30 · Baseline + stance

DORA baseline. Published AI stance. Code Assist in the IDE. Gemini on GitHub reviews on request. Capability self-assessment #1.

Days 31–60 · Context + small batches

Context files, an approved MCP list, Gemini CLI with checkpoints. Jules on small tasks. PR size target agreed and visible.

Days 61–90 · Compare

Gemini CLI in CI for triage. Compare all five metrics against the baseline. Assessment #2. Fix the weakest capability next.

⛔

Rules from day one: no --yolo outside a sandbox. Jules plans are read before approval. A person merges every PR. Don't turn DORA metrics into individual performance targets; they describe teams and systems.

❓ FAQ

Questions teams ask in week one

Gemini CLI, Code Assist or Jules?

Code Assist in the IDE for everyday coding. Gemini CLI for terminal-centric agent work, scripting and CI. Jules for a well-scoped task you want done asynchronously while you do something else.

Can Gemini CLI read our AGENTS.md?

Yes. By default it reads GEMINI.md, and you can configure the context file name in settings.json to include AGENTS.md. Check the settings reference for your version.

Our deployment frequency went up but so did change failure rate. Is AI working?

That's the "amplifier" pattern DORA warns about. Look at batch size, test coverage and review depth. Faster output on weak foundations creates more failures. Shrink PRs and strengthen the platform before you push more volume.

Should we rank developers by DORA metrics?

No. DORA metrics describe the delivery system of a team or service. Using them as individual targets invites gaming and hides the real constraints.

Do we need Google Cloud to use DORA?

No. The metrics and the capabilities model are tool-neutral. Collect them from any CI/CD and incident tooling.

Step 1
🧠 Mental model

The engine routes. The conductor executes. Hooks keep both honest.

In v1, AIDLC was prose the model was asked to follow. In v2 a deterministic engine (a plain program, not AI) decides what happens next, the conductor (your /aidlc chat) does the work, and hooks are small programs the AI tool itself runs at fixed moments: before a tool call, after a write, when you type, when the turn ends.

Engine

Which stage is next, which scope applies, when a gate must block, when a phase boundary is verified. Same state in, same move out.

Conductor

Adopts the agent persona, asks good questions, writes artefacts. Never decides routing: it asks the engine "what next?"

Hooks

Record your turns, write the audit trail, run sensors, refuse out-of-order actions, keep the loop going. The model can't skip them.

ℹ️

Why it matters to you: the hooks are why "the AI approved its own plan" can't happen, why every decision is in the audit trail without anyone writing it, and why a stuck workflow is usually waiting on you at a gate.

🔌 Wiring

Same hooks, wired natively per tool

Every hook routes through the native binary (aidlc engine hook … on Claude Code, aidlc engine adapter copilot … on Copilot). You never edit these files by hand; aidlc config regenerates them.

  • Each entry has both a bash and a powershell command, so Windows works.
  • Copilot shows gates as numbered prose options: its picker returns answers as tool results, which can't prove a human typed. Reply in chat.
  • Stage runners carry disable-model-invocation: true: the agent can't start one by itself.
💡

One process per tool call (2.11): on Claude Code the guard checks before a tool call run in one registration instead of one process each, which saves memory when a stage runs helpers in parallel.

Pick an action and a Guard Policy, and see what the hooks do

Fences refuse actions nothing asked for. Guard Policy decides how far the switchable ones stand aside for this piece of work. Results follow the 2.11 rules.



ℹ️

Defaults: enterprise ships strict; every other shipped scope ships off. A memory file with ## Guard Policy / Mode: strict beats everything except a machine kill switch.

🚧 Fences

The five fences and Guard Policy

Choose a policy to see which fences stay up. Human presence and claimed-Unit write ownership never go down with policy.

FencePer-work switchMachine-wide kill switch

💡

Just ask in plain words: "stop asking me to re-approve when files change" sets Guard Policy relaxed; "turn the guards off" sets off. The agent runs the setter and quotes its one-line result. It will never lower a check on its own or suggest it.

🙋 Presence

Only a real message from you opens a gate

Typing a prompt (or answering a native question box) records a HUMAN_TURN. A stage gate's approval needs one sent after the gate was shown. In 2.11 your reply is read in your own words at every question:


ReplyEngine records
1, approved, looks good, aproveApprove
rename the handlerRequest Changes, with your words as feedback
looks fine but rename the handlerApprove and do the instruction, reported in one line
Approve, but let's stop there for todayApprove and park; /aidlc later carries on
hmm, not sureOne short question back
🤖

Automation: a driver that submits prompts with nobody present must set AIDLC_UNATTENDED to 1 in its own process. Then no HUMAN_TURN is minted and gates keep waiting for a person. That's by design.

📡 Sensors

Sensors check what the agent actually wrote

Rules feed the agent forward; sensors feed back. They fire from run-sensors on matching writes, or once per deliverable at the gate. Findings are advisory in this release: an audit row plus a detail file, and the gate tells you which checks still report findings.

SensorFires onChecks
claim-sourcesIntent Capture outputs (gate)Every claim carries a source tag; kept assumptions match what you confirmed
required-sectionsRecord-dir Markdown (gate)Required H2 headings are present
upstream-coverageRecord-dir Markdown (gate)Deliverables reference each upstream artefact the stage consumes
traceabilitytraceability.jsonUpstream IDs covered; downstream targets exist
linter.ts/.js writesYour configured linter (ESLint by default)
type-check.ts/.tsxtsc. Since 2.11 it runs at Build and Test, not after every generated file
audit/ shard (excerpt)written by hooks, never by hand
### Sensor Failed - Stage: requirements-analysis - Sensor: required-sections - Detail: <record>/.aidlc-engine/sensors/requirements-analysis/required-sections-20261011T0914Z.md missing: "## Non-Functional Requirements"
➕

Add your own: write a sensor manifest (an aidlc-<id>.md in the harness's sensors/ folder) and list its id in the stages that should run it, or confirm a sensor proposal at a learning gate and AIDLC installs it for you (SENSOR_PROPOSED). /aidlc --sensors off turns them off for one piece of work.

🎚️ Ceremony

Five ceremony switches, owned by the scope

Each scope sets defaults; you override them per piece of work. None of them removes an approval gate except plan approval, which is the approval it names.

SwitchPer-work flagWhat "off" removesDefaults
sensors/aidlc --sensors offSensor runs and gate checkson (express: off)
learnings/aidlc --learnings offmemory.md diary + "Anything to add for next time?"on (bugfix, express: off)
summary confirmation/aidlc --summary-confirmation onThe "Looks correct?" checkpoint before outputsoff on classic, bugfix, express

collaborators/aidlc --collaborators onSupport agents (spokes, mob round, pipeline link)off everywhere except enterprise

Check what's in force with /aidlc --status or /aidlc config list. Each value shows where it came from, e.g. Plan Approval: off (from scope poc) or Guard Policy: relaxed (set by you).

🔧 Troubleshoot

"It's stuck" or "my approval wasn't recorded"

Since 2.11, when a tool runs no AIDLC hooks, the first reply stops and names the one step for that tool, instead of letting approvals go unrecorded.

ToolThe fix it names
Claude CodeApprove project hooks via /hooks, then fully restart (not /clear). Remove a disableAllHooks setting; allowManagedHooksOnly needs an admin.
VS CodeTrust the workspace and turn on Chat: Use Hooks for the folder.
Copilot CLITrust the folder at the interactive prompt; headless runs need the repo-hooks env variable.
Codex CLIType /hooks, press t to trust all, then Esc.
Kiro CLI / IDECLI: /agent and pick aidlc. IDE: trust the folder and reload the window.
read-only diagnostics
$ aidlc doctor --verbose # every check, with fixes $ aidlc engine audit history # the audit timeline $ aidlc engine log answers --stage requirements-analysis $ aidlc engine now # engine's clock
⛔

Don't "fix" by hand. Never edit aidlc-state.md, the audit/ shards, or the generated hook files. The state-transition guard refuses those writes and names the sanctioned route (engine log decision|answer, engine orchestrate report). Hooks are protected from being invoked by the model too, so the agent can't forge your turn.

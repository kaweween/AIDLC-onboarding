🔭 Overview

From prompt rules to a deterministic engine

AI-DLC still follows the AWS methodology (AI proposes, humans approve, everything recorded), but the implementation is now an engine with hooks, a shared workspace and a native installer.

5 / 33

Phases / stages: Initialization, Ideation, Inception, Construction, Operation.

14

Agents: 11 domain experts, 2 reviewers (product lead, architecture), 1 composer.

11

Scopes, from express (≤10 stages) to enterprise (33), plus composed plans.

118

Audit event types, written by hooks into per-clone shards.

0 Initialization→1 Ideation→ gate →2 Inception→ gate →3 Construction→ gate →4 Operation↺

Phase boundaries run verification gates (traceability, orphaned artefacts). Construction repeats per Unit of work; Operation's last stage can loop back to Ideation.

⚠️

Changed defaults in 2.11 matter if you upgrade with work in flight: an in-flight intent keeps its recorded Guard Policy and ceremony, but plan approval and collaborators follow the scope's new defaults. Outside enterprise it continues lead-agent-only unless you type /aidlc --collaborators on.

⌨️ Commands

The commands you'll actually use

In chatDoes
/aidlc <describe work>Start (scope detected, or a compose offer for rich prose)
/aidlcCarry on with the work in progress
/aidlc bugfix|express|feature|classic … Start with a named scope (runners: /aidlc-bugfix, -express, -feature, -mvp, -security-patch)
/aidlc compose "…"Tailored plan; also mid-workflow to reshape pending stages
/aidlc --status · --doctor · --helpRead-only status, health check, usage
/aidlc --stage <slug> · --phase <name>Jump (skipped stages marked [S]; jumping back reopens)
/aidlc --stage <slug> --singleRun one stage in isolation (or /aidlc-<stage>)
/aidlc --skip <stage> · --add <stage>Change the plan now; the reply names the way back
--depth · --test-strategy · --reviewminimal/standard/comprehensive · adversarial/advisory/none
--guard-policy · --sensors · --learnings · --summary-confirmation · --plan-approval · --collaboratorsPer-work ceremony and guard settings
/aidlc park · intent … · space …Park; list/switch/archive intents; team spaces
/aidlc knowledge onboard|sync|list|show|summarizeDocumentKB
/aidlc-session-cost · /aidlc-replay · /aidlc-outcomes-packRead-only reports; outcomes-pack writes OUTCOMES.md
In the terminalDoes
aidlc config [--harness X] [--dry-run]Set up or refresh a project
aidlc doctor [--verbose]Check machine + project, with fixes
aidlc update · use · version · uninstallManage the machine install
aidlc config models|providers|trust|flags --showInspect settings
aidlc attest resolve|anchorCommit provenance

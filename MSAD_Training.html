Microsoft Agentic DevOps: Training Path

Six modules from first prompt to an ops loop with people approving. About 9 hours in total, with a hands-on lab in each module and a knowledge check at the end.

L100 → L300~9 h6 labs12-question check
⌂ All guides
ℹ️

Before you start: read the Onboarding guide. Labs assume a GitHub org with Copilot Business/Enterprise, VS Code, and an Azure dev subscription. Use a sandbox repo, not production.

Modules

L100

M1 · Agentic DevOps concepts

45 min
  • Assistant vs agent vs autonomous agent. Synchronous (agent mode) vs asynchronous (coding agent).
  • The tool map across Ideation → Inception → Construction → Operation.
  • What stays human: intent, approval, merge, production.
Lab 1: For the last five tickets your team closed, mark each one "agent mode", "coding agent" or "human only" and say why. Compare with a peer.
L100

M2 · Copilot agent mode in the IDE

90 min
  • Ask / Edit / Agent / Plan modes, and approving tools and terminal commands.
  • Context: #file, #codebase, workspace instructions.
  • Undo and checkpoints. When to stop and restart a conversation.
Lab 2: Do Sim 1 step 2 for real: have agent mode build, test and fix one failing test. Use Plan mode first.
L200

M3 · Steering: instructions, prompts, custom agents, MCP

90 min
  • copilot-instructions.md, path-scoped *.instructions.md (applyTo), AGENTS.md.
  • Prompt files (*.prompt.md) and custom agents (*.agent.md): role, tools, handoffs.
  • MCP: VS Code mcp.json vs coding agent repo settings. Approved server list.
Lab 3: Write a 40-line instructions file and one custom "test-writer" agent. Ask the same question with and without them and compare the answers.
L200

M4 · Copilot coding agent and PR review

2 h
  • Writing agent-ready issues: outcome, acceptance criteria, constraints, files to look at.
  • copilot-setup-steps.yml, the firewall and the copilot environment.
  • Reviewing agent PRs: @copilot comments, Copilot code review, CodeQL and Autofix, separation of duties.
Lab 4: Assign two independent issues to Copilot at once. Iterate on one PR at least twice with @copilot comments. Record the review time.
L300

M5 · Spec-driven delivery with AI-DLC (or Spec Kit)

2 h
  • AI-DLC on the Copilot harness: scopes, gates, Units, the record in aidlc/.
  • Turning Units into coding-agent issues. Waves from the dependency graph.
  • Spec Kit's constitution → specify → plan → tasks → implement flow, and when it's enough.
Lab 5: Run Sim 2 on a toy service with /aidlc … --scope express, then give one Unit to the coding agent.
L300

M6 · Operations with Azure SRE Agent

90 min
  • Scoping resource groups, run modes (review vs autonomous), incident sources.
  • From incident to GitHub issue to Copilot PR. Post-incident summaries.
  • An autonomy policy table for your team.
Lab 6: In a dev subscription, break something on purpose (for example a bad config value). Let the SRE Agent investigate in review mode and file the issue.

Knowledge check

1. You want Copilot to work on a clear issue overnight and give you something to review in the morning. Which do you use?

2. Where do you install dependencies for the coding agent's environment?

3. How do you give rules that apply only to src/Api/**?

4. What happens to the coding agent's changes?

5. Marcus assigned the issue to Copilot. Can Marcus alone approve and merge the resulting PR?

6. How do you ask the coding agent to change its open PR?

7. Best way for GitHub Actions to deploy to Azure?

8. A safe day-one run mode for Azure SRE Agent?

9. How does an incident root cause become a code fix in the agentic loop?

10. What does AI-DLC add over Spec Kit?

11. You need a framework upgrade and a new feature. How do you ship them?

12. After a month, agent PRs wait days for review. What's the best fix?

Official learning

Microsoft Learn has GitHub Copilot learning paths and the GitHub Copilot certification (GH-300). GitHub Docs has tutorials for the coding agent, custom agents and MCP. Azure SRE Agent docs are on Microsoft Learn. Catalogues change, so search them by name.

📝 Repo

One rules file for every tool

The repo already has AGENTS.md from the other platforms. Instead of copying it, Priya tells Gemini CLI to read it.

.gemini/settings.json (project, committed)
{ "context": { "fileName": ["AGENTS.md", "GEMINI.md"] }, "general": { "checkpointing": { "enabled": true } }, "tools": { "sandbox": "docker" }, "mcpServers": { "ado": { "command": "npx", "args": ["-y", "@azure-devops/mcp", "contoso"] } } }
gemini
> /memory show Loaded context from: ./AGENTS.md, ./src/Billing.Rendering/AGENTS.md > /mcp ado · connected · 12 tools
⚠️

Settings keys have moved between Gemini CLI versions (for example from flat keys to grouped ones). Check the settings reference for your version and keep the file in code review.

⌨️ Commands

Share repeatable prompts as commands

.gemini/commands/smallpr.toml → /smallpr
description = "Split the current change into small, independently deployable PRs" prompt = """ Look at git diff main...HEAD. Propose how to split it into PRs of under 200 changed lines, each one deployable on its own behind a flag if needed. List the order and the tests each needs. Context from the user: {{args}} """

This command puts DORA capability 5, working in small batches, straight into the tool.

🧭 AI-DLC

Using the method without a Gemini harness

AI-DLC doesn't install into Gemini CLI. The team splits the work instead.

Inception in a supported harness

Run /aidlc or $aidlc in Claude Code, Copilot or Codex. The PO and architect approve there. The record in aidlc/ is committed.

Construction with Gemini

Gemini CLI or Jules builds each Unit from its functional design file. Because AGENTS.md is in context, the same rules apply.

What you lose

Hook-enforced gates, guards and the audit trail during Gemini work. Compensate with PR reviews and branch protection.

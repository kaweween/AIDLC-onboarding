Google Gemini + DORA: Training Path

Three modules on the Gemini tools and three on DORA measurement and capabilities. About 8.5 hours in total, with a lab in each module and a knowledge check at the end.

L100 → L300~8.5 h6 labs12-question check
⌂ All guides
ℹ️

Before you start: read the Onboarding guide. Labs need Gemini CLI, a Code Assist licence (or API key for a sandbox), and read access to your CI/CD and incident data for the DORA modules.

Modules · Gemini tools

L100

M1 · Gemini CLI fundamentals

90 min
  • Install, auth options (Google login, API key, Vertex AI), /init, @ file references.
  • Context: GEMINI.md hierarchy, /memory, using AGENTS.md.
  • Approvals, --approval-mode, sandboxing, checkpoints and /restore.
Lab 1: Turn on checkpointing, make a deliberately bad change, and restore it. Then do the same fix in under 150 lines.
L200

M2 · Extending and automating

90 min
  • MCP servers in settings.json; extensions; custom commands in .gemini/commands/*.toml.
  • Headless gemini -p, JSON output, run-gemini-cli in GitHub Actions.
  • Untrusted input (logs, issues) and least privilege in CI.
Lab 2: Write the /smallpr command from Sim 1 and a read-only failure-triage workflow step.
L200

M3 · Code Assist and Jules

90 min
  • Code Assist in the IDE: chat, agent mode, editions, Enterprise code customisation.
  • Code Assist on GitHub: /gemini review, summaries, .gemini/styleguide.md.
  • Jules: environment setup, plan approval, branches and PRs.
Lab 3: Give Jules one small task, change its plan before approving, and review the PR with Code Assist.

Modules · DORA

L100

M4 · The five DORA metrics

60 min
  • Throughput: change lead time, deployment frequency, failed deployment recovery time.
  • Instability: change failure rate, rework rate.
  • Team and system metrics, not individual targets. Avoiding Goodhart's law.
Lab 4: Fill in the calculator with your team's real numbers. Write down where each number came from.
L200

M5 · Instrumenting the metrics

2 h
  • Event sources: commits, PR merges, deploys, rollbacks, incidents, hotfix labels.
  • Defining "failure" and "rework" consistently. Medians, not averages.
  • Dashboards and review cadence (monthly trend, quarterly deep dive).
Lab 5: Compute lead time and deployment frequency for the last 4 weeks from Git and pipeline data. A spreadsheet is fine.
L300

M6 · The DORA AI Capabilities Model in practice

90 min
  • AI as an amplifier: why throughput gains can come with more instability.
  • The seven capabilities and a tactic for each.
  • Running experiments: one capability, one metric, one quarter.
Lab 6: Run the capability assessment with your team and agree on three experiments.

Knowledge check

1. How do you make Gemini CLI follow the repo's existing AGENTS.md?

2. Gemini made a 600-line change you don't want. Fastest safe undo?

3. What should you do before Jules writes code?

4. Where do team review rules for Gemini Code Assist on GitHub go?

5. Which are the two DORA instability metrics?

6. What does rework rate measure?

7. DORA's 2025 one-line summary of AI's effect on teams?

8. Which is NOT one of the seven DORA AI capabilities?

9. After the rollout, deployment frequency doubled and change failure rate rose from 12% to 25%. Best response?

10. Should DORA metrics be individual performance goals?

11. When should you start measuring?

12. Safest setup for Gemini CLI triage in CI?

Official learning

dora.dev has the research reports, capability guides and the Quick Check. Google Cloud Skills Boost and the Gemini Code Assist docs have hands-on Gemini labs. The Gemini CLI repo has a docs folder with tutorials. Catalogues change, so search them by name.

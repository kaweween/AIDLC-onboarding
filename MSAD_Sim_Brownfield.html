Step 1
🏢 Scenario

Old code, new request

billing-service: .NET 6 (out of support), 38k lines, thin tests around exports. Finance wants bulk invoice export (up to 50k invoices to CSV/PDF zip) this quarter.

Risk

Unsupported runtime. Exports run in the request thread today. Nobody wants to touch InvoiceRenderer.

Plan

1) Upgrade the runtime with app modernization. 2) Add the feature through AI-DLC with Reverse Engineering. 3) Operate it with SRE Agent.

People

Marcus (dev), Priya (architect), Tomás (SRE), Sarah (PO).

⬆️ Modernize

Upgrade first, in its own PR

In VS Code, Marcus opens the GitHub Copilot app modernization view for .NET and asks for an upgrade to the current LTS. It assesses, writes a plan, and waits for approval.

🤖 Copilot · App modernization
Marcus
Upgrade billing-service to the current .NET LTS.
Copilot
Assessment: 6 projects, 41 NuGet packages (7 need major bumps), 2 breaking API uses (BinaryFormatter, WebClient). Plan saved to .github/upgrades/dotnet-upgrade-plan.md. Review the plan, then say "start".

Replace BinaryFormatter with System.Text.Json, not a compat shim. Then start.

Upgraded project by project, with a commit per step. Build ✓, tests 388/388 ✓. Summary in dotnet-upgrade-report.md.
💡

Keep the upgrade and the feature in separate PRs. If production breaks, you'll know which change caused it.

🔎 Inception

Understand before changing

With the runtime current, Marcus runs AI-DLC on the Copilot harness. Brownfield detection turns on Reverse Engineering, and the team sets Guard Policy strict.

🤖 Copilot · Agent
Marcus
/aidlc Add bulk invoice export (CSV and PDF zip, up to 50k invoices, async, emailed link). --scope feature --guard-policy strict
AIDLC
Brownfield detected (38k LOC). Reverse Engineering first: architecture, component map, hot spots. Findings: InvoiceRenderer is synchronous and allocates a full PDF in memory; export runs in the API request; there's no job table.
AIDLC · architect agent
Proposed ADR-014: move exports to a Service Bus queue + worker, stream PDFs into a zip on Blob Storage, and email a SAS link valid for 24 h. Alternatives considered: Durable Functions; a larger API tier.
Priya
Approve ADR-014. Add a limit: 5 concurrent exports per tenant.

🚨 Operation

Two days later: an alert at 02:14

Azure Monitor fires "export-worker: dead-letter count > 50". Azure SRE Agent starts investigating before Tomás opens his laptop.

Investigating. Correlated signals:

• Worker exceptions: Azure.RequestFailedException: 409 BlobAlreadyExists
• Deploy history: no deploys in 41 h

SRE Agent
Flag off for fabrikam. Opened issue #318 "Blob name collision in export-worker" with logs, KQL query and suspected line. Assigned to Copilot.

☁️ Coding agent

Prepare the cloud agent's environment

The coding agent runs in a GitHub Actions-powered environment. This workflow runs before it starts, so dependencies are ready and builds don't fail on missing tools.

.github/workflows/copilot-setup-steps.yml
name: Copilot Setup Steps on: { workflow_dispatch: {}, push: { paths: [.github/workflows/copilot-setup-steps.yml] } } jobs: copilot-setup-steps: # the job name must be exactly this runs-on: ubuntu-latest permissions: { contents: read } steps: - uses: actions/checkout@v4 - uses: actions/setup-dotnet@v4 with: { dotnet-version: '8.0.x' } - run: dotnet restore BillingPlatform.sln - run: docker compose -f tests/compose.yml up -d sqledge # local SQL for integration tests
⚠️

Run the workflow once by hand from the Actions tab to prove it works. A broken setup step turns every agent task into a slow failure.

🔌 MCP

Give agents approved tools

MCP servers let agents query Azure resources or Boards work items. Only add servers on the team's approved list.

.vscode/mcp.json
{ "servers": { "azure": { "type": "stdio", "command": "npx", "args": ["-y", "@azure/mcp@latest", "server", "start"] }, "ado": { "type": "stdio", "command": "npx", "args": ["-y", "@azure-devops/mcp", "contoso"] } } }
Settings → Copilot → Coding agent → MCP configuration
{ "mcpServers": { "azure": { "type": "local", "command": "npx", "args": ["-y", "@azure/mcp@latest", "server", "start"], "tools": ["*"] } } }

For the cloud agent, sign in to Azure in copilot-setup-steps.yml with OIDC (azure/login) and a read-only identity. Never use an owner identity.

🧭 AI-DLC

Add the method on top

The same native aidlc command from the AI-DLC setup sim projects skills, agents and hooks into .github/ and .aidlc/. One install serves both VS Code agent mode and Copilot CLI.

PowerShell · billing-platform
PS> aidlc config --harness copilot Writing .github/skills/aidlc*/ .github/agents/aidlc-*.md .github/hooks/aidlc.json .aidlc/ Merged AGENTS.md (AI-DLC block appended; your content kept) Configured the copilot harness. Next: aidlc config trust --harness copilot PS> aidlc config trust --harness copilot --acknowledge --yes Recorded the trust answer in .aidlc/tools/data/harness.json PS> aidlc --doctor ✓ harness copilot · ✓ hooks · ✓ skills 48 · ✓ agents 14 · ✓ workspace aidlc/
ℹ️

In Copilot chat, start the method with /aidlc <what you want>. Its stage outputs (requirements, units, plans) are plain Markdown under aidlc/, so the coding agent can read them when you assign it a Unit.

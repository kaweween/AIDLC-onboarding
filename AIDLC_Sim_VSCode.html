🧭 Surfaces

Four ways in, one shared record

The Copilot harness is one install for two surfaces: VS Code agent mode and the Copilot CLI read the same .github/{skills,agents,hooks} and AGENTS.md. Claude Code reads .claude/. All of them write the same aidlc/ record, so you can switch surfaces mid-feature.

🔐 First open

Open the folder and trust it

VS Code runs repo hooks only in a trusted workspace with Chat: Use Hooks on. aidlc config --harness copilot already put "chat.useHooks": true and "chat.agent.maxRequests": 200 into .vscode/settings.json.

{ "chat.agent.maxRequests": 200, "chat.useHooks": true }
⚠️

Why 200? Agent mode stops after chat.agent.maxRequests requests in one turn (default 50) and waits silently on "Continue to iterate?". A Construction stage easily passes 50 tool calls. The project value wins over your user setting; /aidlc --doctor warns if it's below 100.

Why numbered prose and not a picker? Picker answers return as tool results, which don't fire the trusted UserPromptSubmit hook. While a workflow is running, AIDLC denies the picker and asks in prose, so your typed message is what approves.

🗂️ Agents window

Run several AIDLC chats side by side

VS Code's agent sessions view lists your chats. AIDLC binds each chat to one piece of work (a session binding), so a switch in one window never moves another window's workflow. Click a session:

Agents — billing-service
Sessions
Chat
space · intent
  • New chat + /aidlc with no words carries on with the work this machine has chosen. In a fresh clone with committed work, it names that work and picks it up in one answer.
  • /aidlc intent export-bug in a chat switches that chat; other chats stay on their intent.
  • Two concurrent intents in one space are fully supported. Two chats in different spaces can race on the shared ambient memory copy.
🤝 Subagents

Watching AIDLC's agents work

For delegated stages (Reverse Engineering, Practices Discovery, User Stories, Code Generation) and reviews, the conductor hands work to the native custom agents in .github/agents/aidlc-*-agent.md via VS Code's runSubagent tool.

⚙ runSubagent aidlc-architecture-reviewer-agent: "Review construction/export-query/code-generation…"
⇢ SubagentStart hook: stage rules delivered · identity recorded
⇠ SubagentStop hook: log-subagent · verdict NOT-READY, F-4
GitHub Copilot
Reviewer found F-4 (eager line-item load). Builder re-running…
⚠️

Only what you type counts. VS Code delivers a subagent's written brief to the hooks the same way as your messages; AIDLC recognises the brief and never counts it as your approval. A message you send in the first few seconds after a subagent starts may be mistaken for the brief; if so, you're asked to reply again.

🛑

During Code Generation the developer subagent isn't started until you've approved the plan: the same refusal on VS Code and the CLI.

🔧 Troubleshoot

When VS Code skips the hooks

A skipped hook leaves no message in the chat (the Agent Debug Logs panel shows it). Since 2.11 AIDLC watches for this and fixes what it can:

You
/aidlc carry on
GitHub Copilot
AI-DLC's hooks did not run for your message, so approvals can't be recorded. I'm turning on Chat: Use Hooks in this folder's .vscode/settings.json (VS Code will ask you to allow the edit).
✎ Edit .vscode/settings.json: "chat.useHooks": true [Allow] [Skip]
GitHub Copilot
Fixed. Send your next message here to carry on.
  • If the setting was already on, AIDLC says your organisation has switched it off: ask your admin.
  • Untrusted workspace: hooks never run. Use Manage Workspace Trust.
  • /aidlc --doctor can't see VS Code's switches, but it checks everything else.

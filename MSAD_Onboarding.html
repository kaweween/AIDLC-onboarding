Step 1
🔷 Orientation

Agents work alongside the team at every stage

Microsoft's name for this is Agentic DevOps. AI agents plan, code, review, secure, deploy and run software with people. Agents take the repetitive work. People keep intent, judgement and approval.

Copilot agent mode

A synchronous agent in VS Code (and Visual Studio, JetBrains, Copilot CLI). It plans, edits many files, runs terminal commands and iterates on errors while you watch.

Copilot coding agent

An asynchronous teammate. Assign it a GitHub issue (or an Azure Boards work item). It works in an ephemeral GitHub Actions environment and opens a draft PR for you to review.

Copilot code review & security

Copilot reviews PRs. GitHub Advanced Security adds code scanning, secret scanning and Copilot Autofix suggestions for alerts.

Azure SRE Agent

An operations agent for Azure resources. It watches alerts, investigates incidents, suggests or runs mitigations, and can open GitHub issues for the code fix.

Custom agents & MCP

Team-specific agents (.github/agents/*.agent.md) and MCP servers (Azure, Azure DevOps, your own tools) extend what Copilot can see and do.

App modernization

Copilot app modernization assesses and upgrades .NET and Java apps (framework upgrades, Azure migration fixes) with a plan you approve.

ℹ️

Where AI-DLC fits: the Microsoft stack provides the agents and the plumbing. AI-DLC provides the method: ordered stages, approval gates and a written record. AI-DLC ships a native Copilot harness (aidlc config --harness copilot), so you can run /aidlc inside Copilot agent mode and let the coding agent pick up the Units it produces.

⚠️

Repo hosting matters. The Copilot coding agent, Copilot code review and Agent HQ work on GitHub repositories. Teams on Azure Repos can keep Azure Boards and Azure Pipelines and connect Boards to GitHub, or use agent mode locally without the cloud agent. Check the current Azure DevOps integration docs before you plan a migration.

🔑 Access

What an admin turns on first

Most onboarding blockers are policy settings, not install problems. An org owner works through this list once.

  • Copilot Business or Enterprise seats for the team. The coding agent and org-level custom agents need a paid org plan.
  • Policies → Copilot coding agent: enabled for the org, and for the chosen repositories.
  • Models policy: choose which models the team may use (premium requests count against a monthly allowance).
  • MCP servers policy: allow MCP and agree on which servers are approved.
  • Branch protection / rulesets on main: required reviews and status checks. Agent PRs follow the same rules as human PRs.
  • GitHub Advanced Security (code scanning, secret scanning, push protection) on the repos the agent writes to.
  • Azure: a subscription and resource group for dev/test, an Entra ID app or managed identity with least privilege, and an OIDC federated credential for GitHub Actions (no stored secrets).
  • Azure SRE Agent created in the portal with access scoped to the app's resource groups.

📅 Rollout

A 30-60-90 day rollout for one team

Days 1–30 · Assist

Agent mode in the IDE. Instructions files merged. Copilot code review on every PR. Baseline DORA metrics recorded. No agent touches production.

Days 31–60 · Delegate

Coding agent on labelled, low-risk issues. One custom agent. AI-DLC classic or feature scope for one real epic. SRE Agent in review mode.

Days 61–90 · Orchestrate

Units from AI-DLC go to the coding agent in parallel. SRE Agent files issues that Copilot fixes, and people approve. Compare metrics against the baseline.

⛔

Keep these rules from day one: agents never merge to main by themselves. Agents never get production credentials in their setup steps. A person signs off every production deploy.

❓ FAQ

Questions teams ask in week one

Agent mode or coding agent: which should I use?

Use agent mode when you want to steer while it works, for exploratory or tricky changes. Use the coding agent for a clear, testable issue you can review later as a PR. Several coding-agent tasks can run in parallel.

Can the coding agent push to main?

No. It works on a copilot/… branch and opens a draft PR. Your branch protection and required reviews still apply. The person who assigned the task can't be the only approver of the PR.

Does it see our secrets?

Only what you put in the agent's environment (the copilot environment's secrets and variables, and the setup steps). Keep it to what build and test need. Its internet access goes through a firewall you can configure.

Where do AI-DLC and Spec Kit overlap?

Both turn intent into specs, plans and tasks before code. Spec Kit is a light, file-based flow (constitution → spec → plan → tasks → implement). AI-DLC adds scopes, approval gates, review agents, guards and an audit trail. Use one per piece of work, not both at once.

We're on Azure Repos. Are we stuck?

No. You can use agent mode in the IDE with any Git host, and Azure Pipelines and Boards keep working. The cloud coding agent and Copilot PR review need GitHub. Many teams move the repo to GitHub and keep Boards connected to it.

Will the SRE Agent restart production by itself?

Only if you allow it. In review mode it proposes and you approve. Autonomous actions are bounded by the permissions and run mode you give it. Start in review mode.
